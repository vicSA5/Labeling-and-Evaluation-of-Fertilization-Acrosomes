======================================================================
1. RESUMEN DEL PROYECTO
======================================================================

Nombre: LEFA
Nombre descriptivo: Labeling and Evaluation of Fertilization Acrosomes
Tipo: aplicación de escritorio para Windows.
Propósito: facilitar a biotecnólogos la visualización de imágenes microscópicas multicanal y la clasificación manual del estado acrosómico de espermatozoides.

La primera versión (MVP) NO realiza clasificación automática mediante IA. Sirve para cargar imágenes, agrupar canales de una misma muestra, navegar entre muestras, asignar etiquetas, guardar el progreso y exportar resultados. El nombre lefAI deja abierta la posibilidad de incorporar funciones de IA más adelante, pero no debe afirmarse que ya existen.

Principios:
- No modificar los archivos originales.
- No enviar imágenes ni metadatos a servicios externos.
- Una clasificación por muestra lógica, no una por archivo de canal.
- Guardado automático del progreso.
- Funcionamiento robusto aunque falten canales o haya TIFF ilegibles.
- Interfaz sencilla y utilizable principalmente con teclado.
- Código modular y versionado con Git.

======================================================================
2. OBJETIVOS Y ALCANCE
======================================================================

Objetivos del MVP:
1. Seleccionar una carpeta con imágenes TIFF.
2. Reconocer los archivos y agrupar los canales por número de muestra.
3. Mostrar un único canal cada vez con botones BF, G y B.
4. Advertir cuando falte algún canal, sin descartar automáticamente la muestra.
5. Ajustar contraste, zoom y desplazamiento sin alterar los archivos originales.
6. Clasificar cada muestra con atajos de teclado y botones.
7. Avanzar automáticamente tras clasificar.
8. Corregir etiquetas y navegar entre muestras ya revisadas.
9. Guardar y recuperar el progreso mediante CSV.
10. Exportar las etiquetas y, opcionalmente, un ZIP con los archivos originales organizados por categoría.
11. Empaquetar la aplicación como ejecutable de Windows (.exe).

Fuera del alcance inicial:
- Clasificación automática mediante IA.
- Entrenamiento de modelos.
- Edición o escritura sobre los TIFF originales.
- Base de datos compleja o servidor.
- Colaboración simultánea de varios usuarios.
- Vista simultánea de todos los canales (la decisión actual es mostrar uno cada vez).

======================================================================
3. ENTRADA: ARCHIVOS Y CONVENCIÓN DE NOMBRES
======================================================================

La entrada disponible actualmente es una carpeta de archivos .tiff. Para una misma imagen, los archivos comparten un número y llevan un sufijo numérico que identifica el canal.

Ejemplo:
    8.1.tiff  -> imagen lógica 8, canal BF (brightfield/campo claro)
    8.3.tiff  -> imagen lógica 8, canal G (verde; señal asociada al acrosoma)
    8.4.tiff  -> imagen lógica 8, canal B (azul; señal asociada al núcleo)

Otro ejemplo:
    9.1.tiff
    9.3.tiff
    9.4.tiff

El sistema debe interpretar los tres archivos de la imagen 8 como canales de UNA muestra lógica. No debe mostrar cada archivo como una muestra independiente ni pedir tres clasificaciones distintas.

IMPORTANTE:
- El patrón anterior está basado en los ejemplos disponibles y debe validarse con la carpeta real.
- No asumir que todos los grupos contienen los tres canales.
- No asumir que el orden de archivos devuelto por el sistema operativo es numérico.
- Ordenar por el número de muestra de forma numérica (2 antes que 10).
- Determinar el canal a partir del sufijo final antes de la extensión; por ejemplo, .1, .3 y .4.
- Aceptar al menos la extensión .tiff; decidir si también se admitirá .tif.
- Definir qué hacer con nombres que no encajen con el patrón: listarlos como no reconocidos y avisar; no asociarlos a una muestra por conjetura.
- Si hay subcarpetas con archivos del mismo número, no agruparlos automáticamente sin comprobar la ruta. La identidad debe considerar la ruta relativa o avisar de colisiones.
- Los archivos pueden ser TIFF sencillos o TIFF con metadatos de microscopía; comprobar los ejemplos reales antes de cerrar la implementación.

El usuario seleccionará una carpeta raíz. El programa explorará sus archivos de manera controlada y construirá un inventario.

Ejemplo de inventario interno:
{
    "8": {
        "BF": "8.1.tiff",
        "G": "8.3.tiff",
        "B": "8.4.tiff",
        "resultado": null
    }
}

Este ejemplo es conceptual. En la implementación conviene almacenar rutas completas para abrir los archivos y rutas relativas para guardar una referencia portable en CSV.

4. AGRUPACIÓN Y DETECCIÓN DE CANALES
======================================================================

Para cada muestra lógica:
- Identificar los canales encontrados.
- Registrar cuáles faltan.
- Mostrar solo los botones correspondientes a canales disponibles; los ausentes deben quedar deshabilitados o claramente marcados.
- Mostrar un aviso visible, por ejemplo: "Falta el canal G para esta imagen".
- Permitir ver los canales existentes y clasificar la muestra si el usuario lo decide.
- No interpretar la falta de un canal como una etiqueta biológica.
- No detener toda la aplicación por un archivo ausente o ilegible.

Estados de una muestra:
- Completa: tiene BF, G y B.
- Incompleta: falta uno o más canales.
- Con error: no se ha podido leer uno o varios archivos.
- Pendiente: todavía no tiene etiqueta.
- Clasificada: tiene etiqueta asignada.

Una muestra puede ser incompleta y estar pendiente o clasificada. El estado de integridad de los canales es independiente de la etiqueta biológica.

Al cargar la carpeta, mostrar un resumen:
- Número de muestras lógicas detectadas.
- Número de muestras completas.
- Número de muestras incompletas.
- Número de archivos no reconocidos.
- Número de errores de lectura, cuando puedan detectarse sin cargar todos los archivos por completo.

======================================================================
5. FUNCIONAMIENTO DE LA APLICACIÓN
======================================================================

Flujo general:
1. El usuario abre lefAI.
2. Aparece la pantalla inicial de carga.
3. Selecciona o arrastra una carpeta.
4. La aplicación escanea nombres y agrupa archivos por muestra y canal.
5. Se muestra el resumen y se informa de los archivos no reconocidos o canales ausentes.
6. El usuario entra en el clasificador.
7. Se muestra la primera muestra pendiente, o se ofrece reanudar un CSV anterior.
8. El usuario cambia de canal con BF/G/B, ajusta contraste y visualiza la imagen.
9. Asigna una categoría mediante botón o tecla rápida.
10. La etiqueta se guarda automáticamente y se avanza a la siguiente muestra pendiente.
11. Puede navegar hacia atrás y corregir cualquier etiqueta.
12. Puede guardar/exportar CSV o generar un ZIP organizado por categorías.
13. Puede cerrar la aplicación y reanudar más tarde importando el CSV.

La carga de píxeles debe hacerse bajo demanda, no leyendo todas las imágenes completas al inicio. La interfaz no debe quedarse bloqueada durante operaciones de lectura potencialmente lentas. Para el MVP, implementar carga asíncrona cuando sea necesario y evitar optimizaciones complejas prematuras.

6. DISPOSICIÓN DE LA INTERFAZ
======================================================================

6.1 Pantalla inicial
- Nombre/logo: lefAI.
- Texto breve que explique que permite revisar y clasificar imágenes.
- Zona "Arrastra aquí una carpeta o selecciona archivos".
- Botón "Seleccionar carpeta".
- Botón opcional para importar un CSV de progreso.
- Resumen de los formatos admitidos y la convención de nombres esperada.
- Mini tutorial de los atajos: 1, 2 y 3 para clasificar; flechas para navegar.
- Selector de idioma ES/EN.
- Créditos/información de versión.
- Mensajes claros si no se encuentran archivos válidos.

6.2 Pantalla de clasificación
Diseño sugerido: visor principal a la izquierda y panel de control a la derecha.

Barra superior:
- Nombre o ruta abreviada de la carpeta activa.
- Número de muestra actual y total (ejemplo: "8 / 120").
- Indicador de progreso (ejemplo: "65 clasificadas, 55 pendientes").
- Acción para volver a la pantalla inicial o cambiar de conjunto, con confirmación si hay operaciones pendientes.

Zona central izquierda:
- Visor de imagen grande.
- Mostrar un único canal a la vez.
- Botones BF, G y B cerca de la parte superior del visor.
- Canal seleccionado claramente resaltado.
- Si un canal falta, botón deshabilitado o marcado como ausente.
- Zoom y desplazamiento/pan.
- Ajuste de contraste de -100 a +100, con botón para restablecer.
- Ajuste visual sin escribir cambios en el TIFF original.
- Opcional: mostrar el nombre del archivo que se está visualizando.

Panel derecho:
- Número de muestra e identificador.
- Lista breve de canales presentes/ausentes.
- Aviso visible para muestras incompletas o con errores.
- Sección de clasificación con tres botones grandes:
    1 — Intacto
    2 — Parcial / error (ETIQUETA PROVISIONAL; confirmar)
    3 — Reaccionado
- Indicador de la etiqueta actual si ya está clasificada.
- Botón para quitar/reiniciar la etiqueta, sujeto a confirmación o acción clara.
- Botones anterior/siguiente.
- Estado: pendiente/clasificada.
- Botón para exportar resultados.

Barra inferior o lateral:
- Navegación por flechas.
- Opción para saltar a una muestra por número o elegir de una lista.
- Filtro de pendientes/clasificadas/incompletas, si cabe en el MVP.
- Botón para reanudar desde la primera pendiente.

6.3 Comportamiento visual
- Las etiquetas deben distinguirse con texto y no solo con color.
- Los avisos deben ser legibles, sin bloquear innecesariamente el flujo.
- Los cambios de canal no deben cambiar de muestra.
- Las muestras incompletas no se deben ocultar silenciosamente.
- Si el TIFF no se puede abrir, mostrar el error y permitir seguir con otra muestra.

======================================================================
7. CONTROLES Y ATAJOS
======================================================================

Canales:
- Botón BF: mostrar el archivo del canal 1.
- Botón G: mostrar el archivo del canal 3.
- Botón B: mostrar el archivo del canal 4.

Navegación:
- Flecha izquierda: muestra anterior.
- Flecha derecha: muestra siguiente.
- Los botones anterior/siguiente deben tener la misma función.
- La navegación no debe cambiar automáticamente la etiqueta de una muestra.

Clasificación:
- Tecla 1: Intacto.
- Tecla 2: Parcial / error (pendiente de confirmar si es una categoría única).
- Tecla 3: Reaccionado.
- Los botones de la interfaz ejecutan las mismas acciones.
- Tras asignar una etiqueta válida, guardar automáticamente y avanzar a la siguiente muestra pendiente.
- No sobrescribir una etiqueta anterior de manera accidental sin una acción explícita; si se vuelve a clasificar una muestra ya etiquetada, permitir corregirla y guardar el nuevo valor.

Contraste:
- Deslizador de -100 a +100.
- Valor inicial neutral.
- Botón para restablecer.
- El contraste es una transformación de visualización, nunca una modificación del archivo original.

8. CATEGORÍAS: DECISIÓN PENDIENTE
======================================================================

La propuesta actual es:
1. Intacto
2. Parcial / error
3. Reaccionado

Es necesario confirmar con los biotecnólogos qué significa "Parcial / error":
A) una sola categoría que agrupa casos parciales y problemas de calidad;
B) dos categorías diferentes, lo que modificaría las teclas y el CSV;
C) una etiqueta biológica "Parcial" y un estado técnico separado "Error de imagen".

Recomendación: separar los errores técnicos de lectura de las etiquetas biológicas. Un archivo corrupto o una imagen ilegible no debería clasificarse como si fuera un estado acrosómico. La categoría biológica definitiva debe acordarse con los expertos antes de cerrar el MVP.

9. CONTRASTE, VISUALIZACIÓN Y LECTURA TIFF
======================================================================

Tecnologías sugeridas:
- tifffile para leer TIFF y metadatos compatibles.
- NumPy para manejar matrices de píxeles y transformaciones.
- PySide6 para la interfaz.
- Pillow u otra herramienta solo si se demuestra necesaria; no añadir dependencias sin motivo.

Requisitos del visor:
- Leer la imagen de forma segura y detectar dimensiones inesperadas.
- Investigar con archivos reales si son TIFF de 2D, multipágina, multicanal u OME-TIFF.
- No asumir que todos los TIFF tienen la misma estructura interna.
- Convertir la imagen a una representación visual compatible con el visor.
- Manejar imágenes de 8/16 bits y tipos de datos que realmente aparezcan.
- Normalizar o mapear intensidades para visualización sin perder el dato original.
- Contraste ajustable con límites definidos y predecibles.
- Evitar saturación o visualización negra por una conversión incorrecta de 16 bits a 8 bits.
- Mantener zoom y desplazamiento dentro de una experiencia fluida.
- Mostrar mensajes comprensibles para archivos no compatibles.
- No asumir que el sufijo del archivo garantiza por sí solo el contenido real; confirmar la convención con el conjunto de datos.

El ajuste visual debe trabajar sobre una copia en memoria o una transformación de renderizado. Nunca sobrescribir los TIFF originales.

10. GUARDADO Y RECUPERACIÓN DEL PROGRESO
======================================================================

El programa debe guardar automáticamente después de cada clasificación o corrección. También puede ofrecer un botón "Guardar ahora".

Formato recomendado: CSV UTF-8, legible con Excel y herramientas de análisis.

Campos sugeridos:
- sample_id: identificador lógico de la muestra.
- relative_path_bf: ruta relativa al directorio raíz del archivo BF, si existe.
- relative_path_g: ruta relativa al archivo G, si existe.
- relative_path_b: ruta relativa al archivo B, si existe.
- label: etiqueta biológica.
- status: pendiente/clasificada; puede derivarse de label, pero es útil si se define claramente.
- missing_channels: canales ausentes.
- classified_at: fecha y hora opcional.
- file_signature: opcional, para detectar cambios de archivo; valorar hash o tamaño/fecha según rendimiento.

Ejemplo conceptual:
sample_id,relative_path_bf,relative_path_g,relative_path_b,label,missing_channels
8,8.1.tiff,8.3.tiff,8.4.tiff,Intacto,
9,9.1.tiff,,9.4.tiff,Reaccionado,G
10,10.1.tiff,10.3.tiff,10.4.tiff,,

Reglas:
- Una fila por muestra lógica, no una fila por canal.
- Las rutas se guardan relativas a la carpeta raíz para permitir reabrir el conjunto si se mueve de ubicación conservando su estructura.
- La etiqueta vacía significa pendiente.
- Los canales ausentes deben quedar registrados, pero no deben convertirse en etiquetas.
- Al importar un CSV, validar sus columnas y mostrar errores de formato de manera comprensible.
- Al reanudar, comparar muestras del CSV con las muestras actualmente detectadas.
- Recuperar etiquetas coincidentes.
- Advertir de muestras que estaban en el CSV y ya no están en la carpeta.
- Advertir de nuevas muestras que no aparecen en el CSV.
- Detectar ambigüedades, rutas duplicadas o cambios en archivos cuando sea posible.
- No sobrescribir un CSV elegido por el usuario sin confirmación si el destino ya existe.
- Definir dónde se guarda por defecto el CSV de progreso. Recomendación: ofrecer elegir una ruta y recordar el CSV activo durante la sesión; no escribir datos de progreso dentro de la carpeta original sin que el usuario lo sepa.

11. EXPORTACIÓN DE RESULTADOS
======================================================================

11.1 Exportación CSV
- Exportar todas las muestras, incluidas las pendientes, dejando la etiqueta vacía para ellas.
- Incluir identificadores, rutas y etiquetas.
- Incluir canales ausentes o estado de integridad si es relevante.
- Mantener un formato estable y documentado para análisis posteriores.

11.2 Exportación ZIP opcional
El usuario elige destino y nombre del ZIP. Estructura sugerida:
clasificacion_YYYY-MM-DD/
    Intactos/
    Parcial_error/       (nombre provisional, según categorías definitivas)
    Reaccionados/
    clasificaciones.csv

Reglas:
- Copiar los archivos originales sin modificarlos.
- Copiar a la categoría correspondiente todos los canales disponibles de cada muestra clasificada, conservando nombres o creando subcarpetas que eviten colisiones.
- No incluir muestras pendientes en las carpetas de categorías.
- Avisar de cuántas muestras pendientes se han excluido.
- No descartar en silencio muestras incompletas; informar de que se exportan solo los archivos existentes.
- Evitar sobrescribir nombres idénticos de archivos de distintas subcarpetas. Preservar estructura relativa o resolver colisiones de forma explícita.
- Incluir el CSV de etiquetas en el ZIP.
- Manejar falta de espacio, errores de copia y cancelación sin corromper el conjunto original.
- El ZIP es una copia para distribución/análisis, no un lugar donde modificar los originales.

======================================================================
18. PRUEBAS Y CRITERIOS DE ACEPTACIÓN
======================================================================

Pruebas mínimas:
- Una muestra con BF/G/B se agrupa en una sola entrada.
- Una muestra con solo BF y B aparece como incompleta y avisa de que falta G.
- Un archivo con nombre inválido no se asocia silenciosamente a otra muestra.
- Las muestras 2 y 10 se ordenan correctamente.
- Dos archivos con la misma identidad en subcarpetas distintas no se mezclan sin aviso.
- El usuario puede alternar canales sin cambiar de muestra.
- Los canales ausentes no provocan un cierre inesperado.
- Una etiqueta asignada se guarda en CSV.
- La corrección de una etiqueta actualiza el CSV.
- Reabrir/importar el CSV restaura etiquetas previas.
- Una nueva muestra no presente en el CSV se marca como nueva.
- Una muestra del CSV que ya no existe genera una advertencia.
- El ZIP contiene los canales disponibles de cada muestra clasificada.
- Las muestras pendientes no se colocan en carpetas de categorías.
- Los TIFF originales no se alteran.
- Un archivo ilegible no impide clasificar el resto.
- El ejecutable funciona en un equipo de prueba sin Python instalado.

19. GIT Y TRABAJO EN EQUIPO
======================================================================

No subir:
- .venv/
- imágenes experimentales originales, salvo autorización explícita y una decisión consciente.
- archivos privados o credenciales.
- archivos temporales, builds o ejecutables grandes sin motivo.

Sí subir:
- código fuente.
- README y documentación.
- requirements.txt y requirements-dev.txt.
- pruebas automatizadas.
- pequeños fixtures sintéticos para tests, si no contienen datos sensibles.
- configuración necesaria para reproducir el desarrollo.

Flujo básico:
1. Crear una rama por funcionalidad.
2. Hacer commits pequeños y descriptivos.
3. Ejecutar pruebas antes de integrar.
4. Abrir pull request o revisar cambios antes de fusionar si colaboran varias personas.
5. No versionar resultados ni datos reales por defecto.

Ejemplos de commits:
- feat: agrupar archivos TIFF por canal
- feat: mostrar advertencias de canales ausentes
- feat: añadir atajos de clasificación
- fix: corregir orden numérico de muestras
- test: añadir pruebas de reanudación CSV
- docs: documentar convención de entrada
